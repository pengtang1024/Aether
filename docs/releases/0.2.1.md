# Aether 0.2.1

**The desktop window and the daemon now agree.** 0.2.1 finishes the settings
page audit: every control either drives the real daemon/OS or is an honest,
read-only explanation. It also adds remote-control configuration and makes
in-app update checks real.

## Highlights

- **Update checks are real.** Settings → About has a "check for updates"
  action backed by a new `update_check` RPC. The daemon fetches and verifies
  the signed manifest on a worker thread (downloads keep running) and reports
  idle / checking / up to date / available / downloaded / error. Without an
  update source the panel says so instead of pretending.
- **Background app downloads are a setting.** `app_auto_update` is persisted;
  the periodic updater re-reads it every pass. Turning it off reports a new
  release without downloading it.
- **Remote control (RPC) is configurable in the UI.** Settings → Advanced has
  the listen address, a password-style access token, apply/clear actions and a
  status line. The address binds on the next daemon start; token changes rotate
  live. Non-loopback addresses without a token are refused.
- **Support links actually open.** Documentation, community, feedback, release
  notes and the licence open the real GitHub pages; if no desktop opener can
  start, the toast shows the URL.
- **Every switch follows the real state.** One-way bindings used to hide
  programmatic bounces: enabling the schedule without times showed "on" while
  the daemon never received it, and a refused start-at-login looked successful.
  All switches are now two-way.
- **Reset and PAC are honest.** "Reset UI preferences" restores language and
  theme too; selecting PAC bounces back to the daemon's actual mode and points
  at `AETHER_PAC_URL`.

## Notes

- `.deb` auto-updates download and report `ready`; the daemon does not
  self-install packages. AppImage builds can replace themselves atomically.
- Signing/notarization for Windows and macOS remains deferred; Linux is the
  release gate.
- See `docs/SETTINGS_AUDIT.md` for the per-control map and the explicit
  boundaries (read-only paths, launch configuration, external accounts).
