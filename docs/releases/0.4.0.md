# Aether 0.4.0

**A reliability release: the download path now survives crashes, bad sources
and awkward disk layouts — and the aria2 bridge has a real lifecycle.**

[![Made with Slint](https://raw.githubusercontent.com/slint-ui/slint/master/logo/MadeWithSlint-logo-whitebg.png)](https://slint.dev)

## Highlights

- **aria2 compatibility is hardened.** The shared 6800 listener speaks HTTP,
  WebSocket and native JSON-lines. The bridge now persists inline
  `addTorrent`/`addMetalink` payloads under `<data>/aria2-blobs` (served by the
  daemon, surviving restarts), supports `changeOption` for live HTTP limits,
  `changePosition`, `getPeers` from BT peer snapshots, `saveSession` export,
  HTTP keep-alive, and whole-task mirror failover that only switches between
  mirrors with the same size and strong ETag. `system.multicall`, CORS and the
  `token:<secret>` convention remain.
- **Services have one lifecycle.** A new `ServiceSupervisor` owns every
  `kind: "service"` plugin with per-service slot locks, crash respawn and
  status reporting. Enable/disable, rescan, install and uninstall all call the
  same `sync`; the settings page shows `Running`, `Not started` and the last
  error. The old bespoke `PluginBridge`/`spawn_aria2_bridge` path is gone.
- **Downloads survive failures.** Paused tasks no longer flip back to running
  on the next progress sample. Dead plugin processes fail and retry their
  tasks; a no-progress watchdog frees a stalled concurrency slot. Mid-stream
  read resets/timeouts are retryable, range support is verified with a real
  Range probe, 416 discards stale resume state, and a panicked worker can no
  longer be mistaken for a completed preallocated file.
- **Integrity and finalization.** Task-level SHA-256 (`add`/aria2
  `checksum=sha-256=<hex>`) is verified by the Host at finalization, not just
  trusted from the plugin. Finalization validates every file before moving
  any, never overwrites after 999 name collisions, and checks both the staging
  and destination filesystems for space.
- **Disk layout.** "Save as" targets on another filesystem stage in
  `.aether-staging` next to the target so finalization is a rename; a failed
  hidden staging folder falls back to the centralized root. Crash residue is
  cleaned on boot for completed/deleted tasks.
- **Task drawer + plugin page.** BT tasks show seeding state, ratio, uploaded
  bytes, seed time and peer count from the daemon's `task_detail` stream.
  Service plugins show running/stopped/error in Settings → Plugins.
- **Plugin protocol API 2.** Service/bridge/detail commands are a breaking
  addition. All first-party plugins ship rebuilt with `api: 2`; an `api = 1`
  package is rejected instead of failing at runtime.
- **Legal/dependency wave.** The privacy policy and SECURITY notes match the
  real data flows; task data is owner-only on Unix; the full licence bundle
  (including per-crate attribution) ships in every artifact; `cargo-deny` now
  audits the 16 plugin dependency trees. Dependencies include the librqbit
  9.1 / quick-xml 0.41 / suppaftp 10.0.2 / hickory-resolver 0.26.3 security
  updates.

## Notes

- **API 2 is a breaking plugin change.** Upgrade the Host and all plugin
  packages together; the daemon refuses `api = 1` plugins.
- aria2's remaining boundaries: BitTorrent per-task limits are session-wide
  (librqbit), web seeds are not supported, and `getPeers` peer IDs /
  instantaneous speeds / seeder flags are placeholders. Mirror failover is
  whole-task and requires identical size + strong ETag; it does not splice one
  range across untrusted sources. Task-level checksums require a single file.
- The aria2 listener is loopback-only by default; exposing it on a network
  still requires a token, and TLS is not provided (use a trusted network or an
  SSH tunnel).
- Windows cross-volume staging uses volume metadata with a centralized
  fallback; the Windows CI runs the reflexive check, but a true two-volume
  runner is still the acceptance gap.
- Linux x86_64/arm64 `.deb` and AppImage remain the release gate. Windows and
  macOS artifacts are unsigned/not notarized.

## Packaging

- Linux x86_64 and arm64: system `.deb` and portable `.AppImage`, built on
  Ubuntu 22.04 (glibc 2.35+).
- Windows x86_64 and arm64: Inno Setup installer and portable `.zip`, static
  MSVC runtime.
- macOS universal (Apple Silicon + Intel) `.dmg`, macOS 11+, ad-hoc signed.
