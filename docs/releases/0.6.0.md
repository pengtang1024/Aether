# Aether 0.6.0

**A pluginization release: the app is now a controller plus a display. Plugin
settings, behaviour tags and task details come from the manifest instead of
hardcoded plugin ids.**

[![Made with Slint](https://raw.githubusercontent.com/slint-ui/slint/master/logo/MadeWithSlint-logo-whitebg.png)](https://slint.dev)

## Highlights

- **Configure plugins from the UI.** A manifest may declare `settings_schema`
  (bool / int / float / string / select / path / secret / multiline, with
  defaults, ranges and options). The daemon validates every write and stores it
  in the 0600 SQLite database; the plugin list grows a configure button that
  opens a modal form (switch, combo box, masked secret). Stored values are a
  default layer for new tasks — a task's own `settings` still win. CLI
  equivalents: `aether-cli remote plugin-settings` and `set-plugin-settings`.
- **Behaviour tags instead of plugin ids.** `features` is a free-form manifest
  list that grants no permission: BitTorrent declares `torrent`, and the
  speed-limit refusal plus the torrent badge key off that tag. A new plugin of
  the same kind needs no Rust change.
- **The task drawer is schema-driven.** The daemon ships each plugin's
  `detail_schema`; the drawer renders metric rows (speed / ETA / size) and a
  peers table in schema order for the task's own plugin, skipping `logs` and
  unknown section types. The HTTP plugin now emits a 1 Hz `Detail` payload, so
  HTTP tasks get the same detail rows BT had.
- **Clipboard detection follows the installed plugins.** `ipfs://`, `s3://` and
  any other declared scheme is picked up automatically; the old hardcoded list
  is only a fallback when the daemon is not reachable.
- **The tray is Slint's cross-platform `SystemTrayIcon`.** macOS gets a menu-bar
  tray, ~1.4k lines of hand-written D-Bus/Win32 protocol code are gone, and the
  Wayland/X11 show-window regressions are fixed.

## Upgrading

`dpkg -i aether_0.6.0_amd64.deb` replaces an older install in place. Plugin
manifests are API 2 in both 0.5 and 0.6, so an existing plugin directory keeps
working. A daemon from a different version is now shown explicitly in the UI
instead of being mistaken for the app version.

## Known limits

- Plugin credentials live in the 0600 SQLite database (no keyring yet).
- `multiline` plugin settings render as a single-line field; the vendored
  Material `ComboBox` popup can fail to reopen (no first-party plugin declares a
  `select` field today).
- `logs` sections of `detail_schema` are not rendered yet.
- Runtime verification covers HTTP/BT/media paths on Linux; FTP/S3/cloud/RTMP
  and the browser extension remain manually tested.
