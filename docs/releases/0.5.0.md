# Aether 0.5.0

**A polish release: the settings page became searchable, and the tray became a
real second entry point for the window.**

[![Made with Slint](https://raw.githubusercontent.com/slint-ui/slint/master/logo/MadeWithSlint-logo-whitebg.png)](https://slint.dev)

## Highlights

- **Settings search.** A search box in the category rail matches the settings
  themselves, not just page names: type `token`, `socks5` or `端口` and pick
  the row ("Access token"), and the section opens filtered to that row. Cards
  whose own title matches open whole; results are grouped by section with
  counts, the matched term is highlighted, Enter opens the first hit and Esc
  clears the search. The index lives in Rust (`src/settings_search.rs`) with
  Chinese and English vocabulary, and a test guards every card/row id against
  renames.
- **Settings page, reorganised.** The category rail is grouped (Common /
  Applications / System) with the version pinned at the bottom and fits the
  900x560 minimum window. The section header is sticky instead of scrolling
  away. Rows put their control on the title line so long descriptions get the
  full width, read-only paths are selectable fields, and disabled text buttons
  (and plugin uninstall actions) finally look disabled/quiet. The plugin list
  no longer overlaps: 68px rows, status chips, a disabled "Update all" at zero
  updates and an empty state.
- **The tray is a real entry point.** A second launch summons the running
  window (`org.aether.UI` on the Linux session bus, a session-local named event
  on Windows) and only shows the "already running" toast when no tray endpoint
  exists. Closing the window now hides it and keeps the app running whenever a
  tray icon exists — a normal (non-`--silent`) launch used to exit on close.
  The Linux icon re-registers itself when the StatusNotifier host restarts
  (AppIndicator reload, panel restart), so a hidden window can never end up
  without its icon.
- **Ubuntu's tray menu works again.** Three wire-format bugs kept the
  AppIndicator host from building the menu: `GetLayout` used the wrong
  signature, child nodes were serialized with every field boxed as a variant,
  and clicks were only handled for the optional `activate` event while Ubuntu
  sends `clicked`. `GetGroupProperties` and `AboutToShow` were missing too.
  Labels and the tooltip now follow the UI language.

## Notes

- No plugin protocol change: plugins built for 0.4.0 keep working, and every
  first-party manifest still declares `min_host: 0.4.0`.
- macOS still has no tray. Runtime parity (tray, close-to-tray, `--silent`,
  summon) is planned for the 0.5.x line; the DMG ships the window and the
  existing LaunchAgent autostart.
- Tray behaviour depends on the host: GNOME needs the AppIndicator/KStatusNotifier
  extension, KDE and most other panels work natively. Without a host the app
  keeps its window as the only entry point and quits on close, honestly.
- Linux `.deb` + AppImage remain the release gate; Windows and macOS
  artifacts are unsigned/not notarized.

## Packaging

- Linux x86_64 and arm64: system `.deb` and portable `.AppImage`, built on
  Ubuntu 22.04 (glibc 2.35+).
- Windows x86_64 and arm64: Inno Setup installer and portable `.zip`, static
  MSVC runtime.
- macOS universal (Apple Silicon + Intel) `.dmg`, macOS 11+, ad-hoc signed.
