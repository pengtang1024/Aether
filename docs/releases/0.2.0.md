# Aether 0.2.0

**The real download engine, headless.** Aether 0.2.0 replaces the 0.1.0 mock with
a working Rust host: a background daemon, 16 first-party plugins, a plugin SDK,
queueing, retries, throttling, proxies/PAC, signed self-updates and browser
integration.

> The desktop window you see is still the 0.1.0 preview and is **not wired to the
> daemon yet** — it does not start downloads. This release is the engine plus its
> command-line, socket and browser front ends.

[![Made with Slint](https://raw.githubusercontent.com/slint-ui/slint/master/logo/MadeWithSlint-logo-whitebg.png)](https://slint.dev)

## Highlights

- **Background daemon** (`aether-daemon`) on a private Unix socket with a
  JSON-line protocol; single instance, `0600` socket, idle CPU ~0%, ~6 MB RSS.
- **Plugin model**: every protocol is a first-party plugin process with a
  length-prefixed MessagePack contract (`API_VERSION = 1`). 16 plugins ship:
  HTTP/HTTPS/metalink, BitTorrent/magnet, FTP/FTPS, HLS/DASH, WebDAV, S3, SFTP,
  yt-dlp extractor, Thunder, IPFS/IPNS, RTMP/RTSP, Google Drive, OneDrive,
  Dropbox, Baidu Pan, Aliyun Pan.
- **Queueing and control**: `AETHER_MAX_CONCURRENT` with FIFO promotion,
  per-task shared token-bucket throttling, global speed cap, pause/resume/cancel,
  terminal-task delete, and per-task destination directories ("save as").
- **Automatic retries** with exponential backoff that now survive a daemon
  restart, and a cap that actually stops (`AETHER_RETRY_MAX`).
- **Proxies**: system/manual (HTTP/HTTPS/SOCKS5) and **PAC** evaluated in a
  QuickJS sandbox from a URL, `file://` path or inline script — resolved per
  URL, applied to both probing and downloading.
- **Task logs** you can read back (`aether-cli logs`), completion files landing
  directly in the download directory with `-1`, `-2` collision renaming.
- **Signed self-updates**: Ed25519-signed `update.json`, SHA-256 verified
  artifacts, atomic AppImage replacement with `.old` rollback; `.deb` updates
  are downloaded for the package manager, never self-elevated.
- **Browser integration**: MV3 extension + native messaging host, plus
  `aether:`/`magnet:`/`thunder:`/`ed2k:` URL handlers.
- **CLI**: `list`, `probe`, `download`, `tasks`, `logs`, `resume`, `import`
  (batch URLs through the daemon).

## Upgrading from 0.1.0

0.1.0 binaries were withdrawn for missing license notices; there is no supported
upgrade path from it. Install 0.2.0 fresh. The task database migrates
automatically (schema v1 → v3), so any 0.1.0-dev database keeps working.

## Install

- **Debian/Ubuntu**: `sudo apt install ./aether_0.2.0_amd64.deb`, then
  `systemctl --user enable --now aether-daemon`.
- **AppImage**: `chmod +x aether-0.2.0-linux-x86_64.AppImage && ./aether-0.2.0-linux-x86_64.AppImage`
  (the AppImage ships the UI; the daemon/CLI binaries are in the `.deb` and the
  archives).
- **Browser capture**: run `scripts/install-native-messaging.sh` and load
  `browser-extension/` unpacked.

## Known limitations

- The desktop UI is not connected to the daemon yet.
- Windows/macOS packages contain the Host only (no plugins) and the daemon
  requires Unix sockets; Windows named pipes are not implemented.
- ED2K/Kad needs an eDonkey core and is not implemented.
- Baidu/Aliyun shared links need OAuth apps; only official API file IDs work.
- WPAD/DHCP proxy autodiscovery is not implemented (PAC URL/script is).
- Only the first directive of a PAC result is used (no proxy failover).

## Verification

Every asset is listed in `SHA256SUMS`. The `update.json` + `.sig` attached to
this release are signed with the Aether update key; the matching public key is
documented in `docs/UPDATE.md`.
