# Aether 0.3.0

**The plugin layer grew up — and Aether now speaks aria2.** This release makes
the plugin contract enforceable, completes plugin management, deepens the
real protocol engines, turns remote control on by default, and keeps a login
launch quietly in the tray.

## Highlights

- **aria2 JSON-RPC compatibility.** A new `service` plugin shares the daemon's
  single RPC listener: AriaNg and other aria2 clients can point at
  `http://127.0.0.1:6800/jsonrpc` with the token from Settings → Advanced.
  Covered: `addUri`, status queries, pause/unpause/remove, global stats,
  options, session save, `system.multicall`, inline `addTorrent`/`addMetalink`
  payloads, and `ws://…/jsonrpc` notifications for start/pause/stop/complete/
  error. Per-task `changeOption`/`changePosition` are not implemented yet.
- **Plugin capabilities are a contract.** A plugin whose handshake disagrees
  with its `plugin.json` (either direction) is refused, and the catalogue now
  shows each plugin's permissions. Plugins that declare `external-process`
  respect a real setting gate: off means no spawn for new work, idle instances
  stop, running tasks finish.
- **Plugin management is complete.** Uninstall (refused while tasks run),
  rollback to the retained previous version, and version pins that update
  checks skip while manual installs still work. A crashed plugin process no
  longer poisons later commands — the host replaces it on the next call.
- **More protocol work.** SFTP gains private-key and SSH-agent auth (password
  fallback); WebDAV probes with `PROPFIND` for size/ETag; S3 downloads use
  concurrent ranged GETs with resumable prefixes; HLS polls live playlists and
  appends until `EXT-X-ENDLIST`; BitTorrent can select files by index or path
  and keeps seeding until a ratio/time target; Google Drive, OneDrive and
  Dropbox accept a ready access token or an OAuth2 refresh token (your own
  app credentials — none are bundled).
- **Remote control works out of the box.** The first daemon start seeds a
  loopback listener on `127.0.0.1:6800` plus a random token, both persisted in
  `settings.json`. Settings → Advanced shows the address and a masked token and
  can randomise or clear it. A busy port is logged and skipped; non-loopback
  addresses without a token are refused.
- **Silent start.** Login autostart entries now pass `--silent` (alias
  `--minimized`), so signing in brings up the daemon and tray without stealing
  focus. Existing entries are refreshed on boot. If the session has no usable
  tray icon, Aether shows the window instead of hiding out of reach.
- **The Ubuntu tray icon is fixed.** The exported StatusNotifierItem was
  missing the `Menu` property, which Ubuntu's AppIndicator extension treats as
  required; it logged `Unknown property 'Menu'` and dropped the icon. The item
  now announces the `/Menu` dbusmenu it already exported.

## Notes

- The aria2 listener is loopback-only by default; exposing it on a network
  still requires a token, and TLS is not provided (use a trusted network or an
  SSH tunnel).
- Linux x86_64/arm64 `.deb` and AppImage remain the release gate. Windows and
  macOS artifacts are unsigned/not notarized; macOS has no tray implementation,
  so `--silent` falls back to a visible window there.
- Plugin permissions are declared and enforced at the host boundary, not an OS
  sandbox. Live DASH, ED2K, shared-link OAuth for the Chinese cloud drives and
  S3 multipart uploads remain future work.

## Packaging

- Linux x86_64 and arm64: system `.deb` and portable `.AppImage`, built on
  Ubuntu 22.04 (glibc 2.35+).
- Windows x86_64 and arm64: Inno Setup installer and portable `.zip`, static
  MSVC runtime.
- macOS universal (Apple Silicon + Intel) `.dmg`, macOS 11+, ad-hoc signed.
