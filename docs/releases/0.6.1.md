# Aether 0.6.1

**Auto-updates now work out of the box. The daemon carries the release manifest
URL and the official public key, and distro packages download the `.deb`
instead of pretending an AppImage had been applied.**

[![Made with Slint](https://raw.githubusercontent.com/slint-ui/slint/master/logo/MadeWithSlint-logo-whitebg.png)](https://slint.dev)

## Highlights

- **Updates are on by default.** Whether the daemon is started by the desktop
  app or by the systemd user unit, it checks the signed release manifest every
  6 hours. No `~/.config/aether/daemon.env` needed any more; `AETHER_UPDATE_URL`,
  `AETHER_UPDATE_PUBKEY`, `--update-url` and `--update-key` still override, and
  an empty value turns checks off.
- **`.deb` installs get a real update path.** Releases now list installer
  packages (`packages` in `update.json`) next to the portable assets, so a
  distro install downloads `aether_<version>_amd64.deb` when a newer release
  appears and shows `sudo dpkg -i <path>` in the About panel. The daemon never
  escalates privileges itself. AppImage installs keep the in-place atomic swap.
- **Honest update state.** The old build reported `ready` — "restart to apply"
  — after downloading an AppImage it had not replaced. `ready` now means the
  replacement happened; everything else reports `package` with the file it
  downloaded.
- **No more restart storms.** A daemon that finds the socket already served by
  another instance exits successfully instead of failing, so
  `Restart=on-failure` stops retrying (desktop installs had logged thousands of
  attempts).

## Upgrading

- AppImage: replace it in place, or let the next release do it once a build
  with this fix is installed.
- Debian/Ubuntu: `sudo dpkg -i aether_0.6.1_amd64.deb` (or `arm64`). This is
  the last manual step for distro installs: from here on the daemon downloads
  the next package and tells you the command.
- Plugin packages are re-staged by the package; user-installed plugins keep
  their manifest compatibility checks.

## Known limits

- The daemon downloads the installer but does not run it: installing a system
  package needs root.
- Checks are unsigned-or-nothing: a release without
  `AETHER_UPDATE_SECRET_KEY` ships no `update.json`, so that version is not
  advertised to older installs.
- Plugin credentials are still stored unencrypted in the 0600 SQLite database;
  `multiline` plugin settings still render as a single-line field.
